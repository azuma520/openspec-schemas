# tasks.md / plan.md 驗證規則

## PART I — 定義層（結構化）

本節只定義「怎麼從文字取出東西」，不含任何判定。

下述 checks 8-12 皆為 **DETERMINISTIC**：各自依固定規則讀文字決定判定，不含判斷取捨。標註文法與紀錄形狀的定義來自 `tasks` artifact 的指令；這些 check 讀的正是該文法，不另外增加任何東西。

### §L 詞法層

| id | 定義 |
|---|---|
| L1 | `INDENT(x)` = 行 `x` 的前導空白字元數。 |
| L2 | `BLANK(x)` = 行 `x` 不含任何非空白字元。 |
| L3 | `TASKLINE(x)` = `x` 的首批非空白字元依序為 `- [`、**恰一個字元**、`]`。（`- [ ]`、`- [x]`、`- [~]` 一律成立。） |
| L4 | `HEADING(x)` = `x` 的首個非空白字元為 `#`。 |

### §N 巢狀層

設 `t` 為一個 task line，`N = INDENT(t)`。

| id | 定義 |
|---|---|
| N1 | `RANGE(t)` = `t` 之後的行，止於**第一個非空白**且滿足（`TASKLINE(y)` 或 `HEADING(y)`）且 `INDENT(y) <= N` 的行 `y`（不含 `y`）；若無此行則止於檔尾。 |
| N2 | `BELONGS(x, t)` = `x` 屬於 `RANGE(t)` 且 `INDENT(x) > N`。 |
| N3 | **任何** `INDENT(x) > N` 皆成立。不要求特定縮排寬度。 |
| N4 | **空白行透明**：空白行不屬於任何東西、也不終止任何東西；跳過它繼續讀。 |

### §R 紀錄層

| id | 定義 |
|---|---|
| R1 | `RECORD(r, t)` = `BELONGS(r, t)` 且 `r` 去縮排後為 `- RED:` 或 `- GREEN:`。設 `R = INDENT(r)`。 |
| R2 | `RANGE(r)` = `r` 之後的行，止於**第一個非空白**且 `INDENT(z) <= R` 的行 `z`（不含 `z`）。 |
| R3 | `FIELD(f, r)` = `f` 屬於 `RANGE(r)` 且 `INDENT(f) > R` 且 `f` 去縮排後形如 `- <key>: <value>`。 |
| R4 | **一個 field 恰為一行**；其值止於該行行尾。 |
| R5 | `RANGE(r)` 內**不**符合 R3 的行：不是 field、**不是上一個 field 的續行**、不貢獻任何東西、**其存在本身不是錯誤**。 |
| R6 | **CARDINALITY**：同一筆紀錄內，每個 key **至多出現一次**。此規則適用每個 key，不分必填與否。 |
| R7 | `REQUIRED(RED)` = {`subject`, `outcome`, `failure`}；`REQUIRED(GREEN)` = {`subject`, `outcome`}；`invocation` **從不**必填。 |

### §V 值文法

| id | 定義 |
|---|---|
| V1 | `SUBJECT_OK(v)`：令 `w = trim(v)`；由左而右掃描 `w` 尋找兩字元序列 `::`，**比對到就消耗、不重疊**（故 `a:::b` 含**一**次）。成立當且僅當恰好一次**且**其左右兩側 trim 後皆非空。**除此之外一律不限制**——不限路徑寫法、不限副檔名、不限測試名稱字元。 |
| V2 | `OUTCOME_GREEN_OK(v)` 成立當且僅當 `trim(v)` **恰為** token `PASS`。 |
| V3 | `OUTCOME_RED_OK(v)` 成立當且僅當 `trim(v)` 為單一 token、僅含大寫 A-Z、不含空白，**且不為** `PASS`。 |
| V4 | `NONEMPTY(v)` 成立當且僅當 `trim(v)` 不為空字串。 |

### §A 標註文法

| id | 定義 |
|---|---|
| A1 | `TDD_LINE(x, t)` = `BELONGS(x, t)` 且 `x` 去縮排後為 `- TDD: applicable` **或** `- TDD: n/a <SEP> <reason>`，其中 `<SEP>` 為 `—`、`–`、`-`、`--` 四者之一（僅此四者）且 `NONEMPTY(reason)`。**開頭的 `- ` 是必要形式的一部分。** |

### §K 鍵文法

| id | 定義 |
|---|---|
| K1 | `TASKNUM(t)`：`t` 的 checkbox `]` 之後**必須至少有一個空白字元**；其後緊接的 token 若符合 `\d+(\.\d+)*` 則為 `TASKNUM`。`]` 後無空白 → **無 TASKNUM**。該 token 非數字 → **無 TASKNUM**。 |
| K2 | `ENTRYKEY(h)`：**僅**對層級**恰為 `##`** 的標題成立。自 `##` 後第一個非空白字元起取前導 `\d+(\.\d+)*` token；該 token **末位數字的下一個字元必須是空白或行尾**。否則**無 ENTRYKEY**。`###` 或更深**不蒐集**——它是某個 entry **內部**的子標題。 |

## PART II — 判定條件（維持原散文措辭；定義處以 §id 代入）

> 本節**不**提供執行順序或程序。措辭沿用現行條文，只把定義性句子換成 PART I 的 id。

**check 8（TDD 標註存在且形式正確）**：對 tasks.md 裡的**每一個** task line，屬於它的行中必須**恰好有一行**滿足 A1。零行、超過一行、其他形式、或 `n/a` 的 reason trim 後為空 → BLOCK。

**check 9（RED / GREEN 紀錄存在、必填欄位齊備且非空、每個 `subject:` 值合文法）**：對每個標註 `TDD: applicable` 的任務，屬於它的行必須包含**至少一筆** `- RED:` 與**至少一筆** `- GREEN:`。本 check 決定**存在性**；一個任務可帶幾筆紀錄、怎麼配對是 check 11 的問題。每筆紀錄依 R7 檢查必填欄位；缺欄位、欄位值 trim 後為空、或 `subject:` 值不滿足 V1 → BLOCK，點名該值與所屬紀錄。**每一筆**屬於該任務的紀錄都要檢查：第二筆 RED 的缺陷與第一筆同等回報。違反 R6 者 → BLOCK，點名重複的 key 與所屬紀錄。**重複 key 的那個鍵不再跑本 check 的任何 per-value 規則**：其存在性已滿足，cardinality 就是它的 finding，故非空要求與（對 `subject:` 而言）V1 皆不在它身上評值——該 key 恰產出**一條** finding。只有重複的那個 key 被豁免：一筆因 `failure:` 重複而被擋的紀錄，其單一 `subject:` 的文法**仍要**評值，兩條 finding 都報。標註 `TDD: n/a` 的任務不欠紀錄；若仍帶了紀錄，checks 9-11 對它不適用。每一條 finding 都要報，不是只報第一條。

**check 10（outcome 標記）**：本 check **只讀標記**。對屬於該任務的**每一筆**紀錄套用。一筆紀錄帶超過一行 `- outcome:` 時，本 check **不產出任何 outcome 判定**——該紀錄的畸形是 check 9 的 finding。一筆紀錄完全沒有 `- outcome:` 時同樣**不產出判定**——缺欄位是 check 9 的 finding。每筆 GREEN 紀錄的 `outcome:` 須滿足 V2；每筆 RED 紀錄的須滿足 V3。任何不符 → BLOCK，點名該紀錄；每一筆都報。

**check 11（紀錄以 `subject:` 值配對——先各側唯一，再一 RED 一 GREEN）**：紀錄以 `subject:` 的**值**配對，**絕不**依位置；明文禁止序位配對。對每個標註 `TDD: applicable` 的任務，把屬於它的每筆 `- RED:` 紀錄的 trim 後 `subject:` 值依出現順序收成一個 **list**，`- GREEN:` 側收成第二個 list。值以**不透明字串**逐字元比較；值是否合 V1 是 check 9 的 finding，畸形值**仍參與**本 check。完全沒有 `subject:` 欄位的紀錄、以及帶超過一個的紀錄，**兩者都不貢獻**給任一 list。

- **STAGE ONE — 各側唯一性**，在任一 list 化為集合**之前**。某值在 RED list 出現超過一次、或在 GREEN list 出現超過一次，**單獨即為**本 check 的失敗，與另一側無關。逐一點名重複的值與其所在側 → BLOCK。訊息用「超過一次」是因為規則本身如此：出現三次的值是**一個**重複值、報一次。唯一性正是配對之所以可判的原因：兩個同名 subject 各帶一 RED 一 GREEN 時，無從斷定誰配誰。**重跑測試不會多出一筆紀錄**：一個 subject 永遠一 RED 一 GREEN，不論它被執行過幾次。
- **STAGE TWO — 配對**。此時才把兩個 list 化為集合，**雙向**比對並**逐一**回報差異。計數相等**不算通過**。
- stage one 的 BLOCK **不終止** check：stage two 無論 stage one 結果為何都要評估，兩階段各報各的 finding，一次跑完全部。兩者訊息**必須不同**，因為缺陷不同、修法也不同。

**check 12（tasks.md 任務編號與 plan.md entry key 1:1）**：依 K1 蒐集 tasks.md 每個 task line 的 TASKNUM；**task line 在該處的首個 token 不是數字，其本身就是本 check 的一項缺陷**（plan 無法與它 1:1 對鍵）。依 K2 蒐集 plan.md 的 ENTRYKEY。plan.md **完全不存在**時本 check 失敗——`plan` 是本 schema 的必要 artifact，缺席**不得**讀成 vacuous pass，回報為「plan.md absent — no entry keys to compare」而非集合差異。

- **STAGE ONE — 重複**，在化為集合之前，兩側各自**獨立**檢查；任一側有重複即單獨構成失敗。逐一點名 → BLOCK。
- **STAGE TWO — 集合相等**。雙向比對、逐一回報差異；計數相等不算通過。plan.md 存在但**一個 entry key 也收不到**時，亦為本 check 的失敗。
- stage one 的 BLOCK **不終止** check，理由與 check 11 同。

以上任一成立 → BLOCK，且**每一個**成立者都要報，不是只報第一個。

**checks 9-11 的邊界**：這三條只決定**結構、格式與基數**。它們**絕不**決定證據真偽——具名測試是否存在、是否測了任務宣稱交付的行為、記錄的 outcome 是否真的發生過、RED 是否先於實作取得，皆不在此決定；checks 9-11 的任何結果都不構成關於這些事的證據。

**check 12 的邊界**：兩個 stage 合起來就是本 check 名稱裡 1:1 宣稱的全部，不多宣稱任何東西——各側唯一加上集合相等，恰好就是兩組 key 之間的雙射。本 check **只讀 key**；某個 entry 的契約文字是否真的描述了它那個任務，是 review judgement，絕非本 check。

# 你的工作

上面是一份驗證規則。下面是一組待驗的 `tasks.md` 與 `plan.md`。

**只依據上面那份規則**判斷這組輸入的結果，並且**只輸出下面兩行**、不要有任何其他文字：

```
VERDICT: <PASS 或 BLOCK 或 UNDETERMINED>
BASIS: <一句話說明依據>
```

- `PASS` = 依規則沒有任何一條被違反。
- `BLOCK` = 依規則至少有一條被違反。
- `UNDETERMINED` = 規則文字**無法**決定這個輸入該算哪一種。

⚠️ 不要使用任何工具、不要讀取任何檔案、不要搜尋任何程式庫。判斷所需的一切都在本檔內。
